# Figures and exports: references and results (2026-11-23)

`results-engine.md` is generated by the corpus runner, so the checks of
the figure and export features that have no engine computation are
recorded here.

## Box plots: one definition (P-04)

Column and grouped box plots draw the quartiles the column statistics
report and whiskers from a stated rule (`web/src/graph/boxStats.ts`);
Plotly no longer computes its own quartiles.

- Quartiles: the column statistics' percentile method. "linear" is
  Hyndman and Fan (1996) definition 7 (R `quantile(type = 7)`, numpy
  `percentile(method="linear")`), the column statistics' default and the
  only method of grouped column statistics. "prism" (rank (n + 1)p) is
  definition 6 (R `quantile(type = 6)`, numpy `method="weibull"`); the
  reference script checks that the engine's
  `columnstats.percentile(method="prism")` equals it at nine percentiles
  on four data sets.
- Whiskers: Tukey (most extreme values within 1.5 × IQR of the box,
  Tukey 1977) by default; minimum to maximum, 10th to 90th, 5th to 95th
  and 2.5th to 97.5th percentiles (same percentile method) on offer.
- Oracle: numpy 2.x in `/home/eren/opendose/.venv` (R is not installed).
  Script: `web/src/graph/__tests__/reference/box_stats.py`, output
  `box_stats.json`, asserted by `boxStats.test.ts` to 1e-12 relative.

| Data 1, 2, ..., 9, 100 | Q1 | Median | Q3 | Tukey whiskers | 10th to 90th |
|---|---|---|---|---|---|
| type 7 ("linear") | 3.25 | 5.5 | 7.75 | 1 to 9 | 1.9 to 18.1 |
| type 6 ("prism") | 2.75 | 5.5 | 8.25 | 1 to 9 | 1.1 to 90.9 |

`scripts/e2e-figures.mjs` reads q1, median, q3 and the whisker ends from
the drawn trace and compares them with the column statistics table
(prism: 2.75 / 5.5 / 8.25; linear: 3.25 / 5.5 / 7.75).

What changes for a reopened project: a column box plot used Plotly's own
quartiles and now uses the column statistics' method; a grouped box plot
drew minimum-to-maximum whiskers and now draws Tukey whiskers (Graph
settings, Whiskers, brings min-max back). The legend sentence names the
rule ("1.5 × IQR (Tukey)", "minimum to maximum", ...).

## PDF text in embedded fonts (P-02)

PDF exports embed subsets of Inter 4.1 (the plot font) and of Liberation
Sans 2.1.5, renamed OpenDose Sans Classic (metric-compatible with Arial,
the classic theme's font), as CIDFontType2 fonts with Identity-H encoding,
a ToUnicode map and /FontFile2 (`web/src/export/pdfFonts.ts`; fonts made
by `web/scripts/make-export-fonts.py`, OFL 1.1). Checked by
`scripts/e2e-export.mjs` with its own ToUnicode reader and with pypdf as
a second reader: the titles "ΔF/F₀ ≤ 1" and "Ca²⁺ (10⁻⁶ M)" read back
exactly (before: "Delta F/F0 <= 1" and "Ca²? (10-6 M)").

## Raster exports in the plot font (P-03)

An SVG drawn as an image cannot load the page's web font, so PNG, TIFF,
JPEG and WebP exports set Inter text in a system font wherever Inter is
not installed. Raster exports now inline the page's Inter woff2 subsets
the figure's characters need (`web/src/export/webFonts.ts`).

`scripts/e2e-export.mjs` exports the example graph as PNG at 300 dpi at
its on-screen size on a machine without Inter (fallback: Noto Sans) and
compares the X title with two references drawn the same way from the SVG
export's title element, with and without the page's Inter:

| | title ink width | Inter reference | pixel overlap with Inter | with the fallback |
|---|---|---|---|---|
| before | 374 px | 371 px | 0.273 | 0.876 |
| after | 371 px | 371 px | 1.000 | 0.278 |

A width check alone is weak on this machine (Noto Sans comes within
3 px of Inter), so the suite pins both the width (within 1 px) and the
pixel overlap (at least 0.98).

## Large pasted tables (P-10)

`scripts/e2e-large.mjs` pastes 500,000 rows (the plan's acceptance size)
into a new column table (two groups) and a new XY table (X and one Y), in
a fresh browser each, under the shared machine's 4 GB cap for the whole
run (browser and the test script, `browser-slot.sh`), and checks the
numbers shown against `engine/tests/reference/large_tables.py`: t =
-231.4 on 1.000e+6 df and a difference of -0.4005 +/- 0.001731 (scipy);
slope 0.5 (statsmodels OLS 0.49999736); 249903 runs, P = 0.3926 (exact
distribution, 60-digit sums); the residual plots name their 50,000-value
limit. Times and the run's peak memory per phase (dev server, 2026-11-23):

| 500,000 rows | Import dialog | grid | WebGL graph | analysis |
|---|---|---|---|---|
| column, 2 groups | 1.3 s, 1.17 GB | 9.8 s, 2.30 GB | 18 s, 3.09 GB | t test 15 s, 3.72 GB |
| XY, 1 data set | 1.2 s, 1.32 GB | 11.4 s, 2.42 GB | 3.4 s, 2.64 GB | linear regression 15 s, 3.61 GB |

Before (main on 2026-11-23): at 500,000 rows the browser was killed while
the Import dialog parsed the paste. At 200,000 rows the dialog phase
peaked at 2.62 GB (now 0.96 GB) and the browser was killed on Import
under this 4 GB cap; the linear regression gave no result in 15 min (now
7 s; its exact runs test grew as n^2.8); column statistics failed with an
overflow in the Anderson-Darling P. With the paste fixed and before the
analysis-side fixes, the t test phase at 200,000 rows still peaked at
3.24 GB, with two engine workers.

What changed: the pasted text is no longer put in the dialog's text box
above 200,000 characters (a text box of 200,000 lines alone took 1 GB in
Chromium; the dialog says how many lines it holds instead); the paste is
split once (fields sliced from the text, `sourceMatrix`) and shared by the
titles check and the preview; the first lines are read without splitting
the whole text; the table built for the paste report is the import; the
residual diagnostics withhold their per-value points above 50,000 values
(204 MB per answer at 1,000,000); no second engine runtime is warmed
beside a job on more than 4 MB of data; the figure legend, the unit
question and the exclusion counts no longer copy every row on each render
(2.1 GB allocated by the legend alone during one t test at 200,000 rows).
Engine side: `results-engine.md`, "large tables".

Limits that remain:
- The margin under the 4 GB cap is about 300 to 400 MB at the analysis
  (the test script itself holds 0.23 to 0.33 GB of it); one run before the
  last render fixes reached 4.02 GB. The largest remaining consumers are
  the engine worker (Python's memory only grows: about 1 GB after the
  first analysis of 1,000,000 values), the column graph's point layout
  (`ColumnPlot.tsx`) and `numericData`, rebuilt for each engine request.
- The suite is not in `scripts/verify.sh`: it runs in about 2 minutes,
  but verify.sh runs its own Vite dev server (0.5 to 1.3 GB) inside the
  same 4 GB scope, which leaves no room for 3.7 GB.
- A copy from Excel of this size also carries HTML, which the paste
  parses for full-precision values (`parseClipboardHtml`, a DOM of every
  cell); not measured here (the e2e pastes plain text).
