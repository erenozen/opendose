# Figures and exports: references and results (2026-11-23)

`results-engine.md` is generated by the corpus runner, so the checks of
the figure and export features that have no engine computation are
recorded here.

## Box plots: one definition (P-04)

Column and grouped box plots draw the quartiles the column statistics
report and whiskers from a stated rule (`web/src/graph/boxStats.ts`);
Plotly no longer computes its own quartiles.

- Quartiles: the column statistics' percentile method. "linear" is
  Hyndman and Fan (1996) definition 7 (R `quantile(type = 7)`, numpy
  `percentile(method="linear")`), the column statistics' default and the
  only method of grouped column statistics. "prism" (rank (n + 1)p) is
  definition 6 (R `quantile(type = 6)`, numpy `method="weibull"`); the
  reference script checks that the engine's
  `columnstats.percentile(method="prism")` equals it at nine percentiles
  on four data sets.
- Whiskers: Tukey (most extreme values within 1.5 × IQR of the box,
  Tukey 1977) by default; minimum to maximum, 10th to 90th, 5th to 95th
  and 2.5th to 97.5th percentiles (same percentile method) on offer.
- Oracle: numpy 2.x in `/home/eren/opendose/.venv` (R is not installed).
  Script: `web/src/graph/__tests__/reference/box_stats.py`, output
  `box_stats.json`, asserted by `boxStats.test.ts` to 1e-12 relative.

| Data 1, 2, ..., 9, 100 | Q1 | Median | Q3 | Tukey whiskers | 10th to 90th |
|---|---|---|---|---|---|
| type 7 ("linear") | 3.25 | 5.5 | 7.75 | 1 to 9 | 1.9 to 18.1 |
| type 6 ("prism") | 2.75 | 5.5 | 8.25 | 1 to 9 | 1.1 to 90.9 |

`scripts/e2e-figures.mjs` reads q1, median, q3 and the whisker ends from
the drawn trace and compares them with the column statistics table
(prism: 2.75 / 5.5 / 8.25; linear: 3.25 / 5.5 / 7.75).

What changes for a reopened project: a column box plot used Plotly's own
quartiles and now uses the column statistics' method; a grouped box plot
drew minimum-to-maximum whiskers and now draws Tukey whiskers (Graph
settings, Whiskers, brings min-max back). The legend sentence names the
rule ("1.5 × IQR (Tukey)", "minimum to maximum", ...).

## Raster exports in the plot font (P-03)

JPEG and WebP exports set Inter text in a system font wherever Inter is

|---|---|---|---|---|
| before | 374 px | 371 px | 0.273 | 0.876 |
| after | 371 px | 371 px | 1.000 | 0.278 |

## Large pasted tables (P-10)

`scripts/e2e-large.mjs` pastes 500,000 rows (the plan's acceptance size)
into a new column table (two groups) and a new XY table (X and one Y), in
a fresh browser each, under the shared machine's 4 GB cap for the whole
run (browser and the test script, `browser-slot.sh`), and checks the
numbers shown against `engine/tests/reference/large_tables.py`: t =
-231.4 on 1.000e+6 df and a difference of -0.4005 +/- 0.001731 (scipy);
slope 0.5 (statsmodels OLS 0.49999736); 249903 runs, P = 0.3926 (exact
distribution, 60-digit sums); the residual plots name their 50,000-value
limit. Times and the run's peak memory per phase (dev server, 2026-11-23):

| 500,000 rows | Import dialog | grid | WebGL graph | analysis |
|---|---|---|---|---|
| column, 2 groups | 1.3 s, 1.17 GB | 9.8 s, 2.30 GB | 18 s, 3.09 GB | t test 15 s, 3.72 GB |
| XY, 1 data set | 1.2 s, 1.32 GB | 11.4 s, 2.42 GB | 3.4 s, 2.64 GB | linear regression 15 s, 3.61 GB |

Before (main on 2026-11-23): at 500,000 rows the browser was killed while
the Import dialog parsed the paste. At 200,000 rows the dialog phase
peaked at 2.62 GB (now 0.96 GB) and the browser was killed on Import
under this 4 GB cap; the linear regression gave no result in 15 min (now
7 s; its exact runs test grew as n^2.8); column statistics failed with an
overflow in the Anderson-Darling P. With the paste fixed and before the
analysis-side fixes, the t test phase at 200,000 rows still peaked at
3.24 GB, with two engine workers.

What changed: the pasted text is no longer put in the dialog's text box
above 200,000 characters (a text box of 200,000 lines alone took 1 GB in
Chromium; the dialog says how many lines it holds instead); the paste is
split once (fields sliced from the text, `sourceMatrix`) and shared by the
titles check and the preview; the first lines are read without splitting
the whole text; the table built for the paste report is the import; the
residual diagnostics withhold their per-value points above 50,000 values
(204 MB per answer at 1,000,000); no second engine runtime is warmed
beside a job on more than 4 MB of data; the figure legend, the unit
question and the exclusion counts no longer copy every row on each render
(2.1 GB allocated by the legend alone during one t test at 200,000 rows).
Engine side: `results-engine.md`, "large tables".

Limits that remain:
- The margin under the 4 GB cap is about 300 to 400 MB at the analysis
  (the test script itself holds 0.23 to 0.33 GB of it); one run before the
  last render fixes reached 4.02 GB. The largest remaining consumers are
  the engine worker (Python's memory only grows: about 1 GB after the
  first analysis of 1,000,000 values), the column graph's point layout
  (`ColumnPlot.tsx`) and `numericData`, rebuilt for each engine request.
- The suite is not in `scripts/verify.sh`: it runs in about 2 minutes,
  but verify.sh runs its own Vite dev server (0.5 to 1.3 GB) inside the
  same 4 GB scope, which leaves no room for 3.7 GB.
- A copy from Excel of this size also carries HTML, which the paste
  parses for full-precision values (`parseClipboardHtml`, a DOM of every
  cell); not measured here (the e2e pastes plain text).

## Raincloud plots and violins with a stated bandwidth (P-53)

A new column graph kind, Raincloud (half violin, box and points; Allen
et al. 2019, Wellcome Open Res 4:63), and violins whose outline is the
density OpenDose computes itself (`web/src/graph/kde.ts`,
`violinTraces.ts`) instead of the one Plotly picks:

- Kernel: Gaussian; bandwidth: Silverman's rule of thumb as R's
  `bw.nrd0`, h = 0.9 min(SD, IQR / 1.34) n^(-1/5), IQR by R type 7, the
  SD when the IQR is 0. A group with fewer than 2 values, all values
  equal, or a value of 0 or less on a log10 axis gets no density, and the
  legend names it with the reason. On a log10 Y axis the density is of
  log10(values) and the legend says so.
- Grid: R `density()`'s 512 points from min - 3h to max + 3h; each
  group's outline is scaled to the same width (the legend says so).
- Quartile lines (violin) and the box (raincloud): the column
  statistics' quartiles and whisker rule (`boxStats.ts`, P-04).
- Oracle: `web/src/graph/__tests__/reference/kde.py`: numpy for bw.nrd0,
  scipy.stats.gaussian_kde with bw_method = h / SD (its kernel SD is then
  h; checked to 1e-12), itself checked against the kernel sum written
  out. R is not installed. `kde.test.ts` asserts the bandwidth to 1e-12
  and the density at 10 grid points of 8 data sets to 1e-10 relative.

| Example column table | n | h (bw.nrd0) | legend | peak density |
|---|---|---|---|---|
| Control | 6 | 1.06637 | 1.07 | 0.180862 |
| Treated A | 6 | 0.657106 | 0.657 | 0.29611 |
| Treated B | 6 | 0.867852 | 0.868 | 0.220509 |

`scripts/e2e-figures.mjs` opens the example column table, switches its
graph to Raincloud, reads the legend ("Gaussian kernel, bandwidth by
Silverman's rule of thumb (R bw.nrd0): 1.07 (Control), 0.657 (Treated
A), 0.868 (Treated B)"), compares the drawn cloud's width at 30 grid
points with scipy's density (largest difference 7e-15), the box with the
column statistics' quartiles (Control 22.725, 24, 25.275) and the 18
points; then a violin's quartile lines (22.725, 24, 25.275).

Existing kinds are unchanged: a violin saved before keeps Plotly's
violin, its mean line and its legend ("Kernel density (violin) with the
mean (line)"); violins created from now on start with the stated density
and quartile lines (Graph settings, Violin, switches between them).

## Text and line sizes in points (P-54)

Format graph and Format axes take sizes in pixels (as before) or in
points ("Sizes in", kept per browser). The format still stores CSS px,
so every saved graph draws exactly as before: a value typed in pt is

a size of p pt at p pt; the export panel says so when scaling is on.

graphics matrices in force): every tick label at 7 pt, the axis lines
and ticks stroked at 1 pt (10 strokes).

## A colour pinned to a group name (P-56)

Preferences, under "Same colour for a group on every graph", pins a
colour to a group name ("KO" = #d55e00). The pins are project data
(`Project.groupColors`, saved in the file and carried by share links, not
kept per browser); every graph in the workbench and on layout pages
draws a data set of that name (ignoring case and surrounding spaces) in
it, the same colour in light and dark and in print-colour exports. A
colour set on the graph still wins; a pin wins over "same colour for a
group", which only picks a palette slot (`web/src/graph/nameColors.ts`).

Approved data-model change. Migration: a file or share link without
`groupColors` loads with no such key, so it opens, draws and saves

tables with or without pins (pins are not table data).

The palette check runs on the pins and warns, never refuses: a pin under
3:1 contrast on white (the export paper) or on the dark export
background (#1c1c1e), and pairs of pins closer than CIEDE2000 10 for

`scripts/e2e-figures.mjs` opens three tables with KO first, second and

## Brackets for pairs of rows on the contingency graphs (P-14)

The pairs of rows of an r x c table (`contingency.pairwise_rows`, its
engine validation is in `results-engine.md`) are drawn as brackets on the
stacked contingency graphs (% of each row, counts), one bracket per pair
joining the two rows' stacks, labelled with the adjusted P (a q value
under Benjamini-Hochberg) the results table shows, in the analysis's P
style; asterisks or the exact P are chosen in Pairwise comparisons, and
the legend states the test per pair, the family ("with P values
adjusted for 3 comparisons (Holm)"), the star scale and where the exact
values are (`sheets/contingency/brackets.ts`). The bracket layer
measures a category X axis by category index and stacked bars by the sum
of their segments (`graph/apply.ts measureTraces`); other graphs measure
exactly as before (the same traces). The percent axis grows above 100%
to hold the brackets and keeps its ticks at 0 to 100%. Grouped bars draw
a cluster per row, where a bracket between rows has no single bar to
join: they draw none, and the graph options and the legend say why; so
do rows that share a name. Compact letters are not offered for rows.

Reference: the plan's acceptance data, WT 18/20, Het 15/20, KO 5/20
positive (`engine/tests/reference/pairwise_proportions.py`: scipy per
pair, statsmodels `multipletests("holm")`): Holm-adjusted P 0.4075 (WT
vs. Het), 3.719e-4 (WT vs. KO), 0.008853 (Het vs. KO).

`brackets.test.ts` checks the comparisons (adjusted P, the q-value
label, a pair without a test counted as unmatched), the refusals, the
measured stack tops (row totals 20), the bracket positions on the
percent graph (WT 0, Het 1, KO 2; heights 110, 120, 130; labels P =
0.4075, P = 0.0089, P = 0.00037) and on the counts graph (22, 24, 26),
and the legend in its four forms. `scripts/e2e-figures.mjs` opens the
three graphs bound to a Holm contingency analysis and checks the results'
adjusted P (0.4075, 3.719e-4, 0.008853), the brackets and their labels
(ns, **, ***; and the exact P), the axis top above 130 with ticks to
100%, the dialog's list and its missing letters tab, the legend, and the
grouped graph's refusal. `scripts/e2e-export.mjs` finds the three labels
in the SVG export.

## The equivalence margin on the estimation plot (P-12)

When the family holds a t test (unpaired, Welch or paired) with an
equivalence or non-inferiority margin, its estimation plot of the same
two groups draws the margin as dashed lines across the difference's
column (labelled "margin −1", "margin +1"; one line for non-inferiority)
and the t test's 90% CI (the 1 - 2 alpha interval of the two one-sided
tests, Schuirmann 1987) as a capped bar beside the bootstrap CI, on the
difference axis, which grows to hold them (`report/estimation/margins.ts`,
`figure.ts`). The t test states A - B and the plot shows test - control:
with A as the plot's control the margin and the interval are mirrored
(-0.6403 to 0.2403 for B - A), and the legend says "drawn as B minus A".
Nothing is drawn, and the legend says why, for a ratio margin, an effect
size other than the mean difference, a paired test against an unpaired
plot (or the reverse) and a plot without that pair. Without such a t test
the figure is the same object as before (checked in `margins.test.ts`);
frozen estimation graphs draw no margin (their snapshot holds their own
result only). The legend under the graph, the report card, the
PowerPoint notes and the export bundle read the same t test.

Reference: the P-12 e2e data (A = 10.8, 10.75, 10.55, 10.5, 9.6, 9.65,
9.85, 9.9; B = A - 0.2), `engine/tests/reference/equivalence_tost.py`
(statsmodels `ttost_ind`): A - B = 0.2, 90% CI -0.24032753 to 0.64032753,
margin ±1, P (TOST) 0.00321.

`margins.test.ts` checks the sheet lookup, both orientations, the
non-inferiority bound on either side, the five reasons for leaving the
margin off, the Gardner-Altman figure (lines at y2 = -1 and 1 from x =
1.78 to 2.7, the CI marker at x = 2.06 with ends -0.6403275 and
0.2403275, the axis range) and the legend sentences.
`scripts/e2e-figures.mjs` opens a family with the t test (margin 1) and
the estimation plot and reads the two lines, the CI ends (to 5e-5) and
the legend; a paired t test against the unpaired plot draws nothing and
says why. `scripts/e2e-export.mjs` finds the margin labels and the dashed
lines in the SVG export.

## Excel workbook of the tables and results (P-64, 2026-11-24)

File, Export tables and results to Excel (.xlsx), writes one workbook: a
README sheet, then one sheet per data table and one per results sheet.
The writer is TypeScript with fflate (`export/xlsx.ts`, as
`export/pptx.ts` writes PowerPoint): no engine call, no extra download,
and a project's workbook is built in milliseconds, where openpyxl in the
worker would first wait for the engine. Each sheet holds exactly the rows
of that table's or results sheet's CSV export (`export/workbook.ts`): a
field that reads as a plain decimal number is a number cell (Excel
right-aligns and sums it), everything else is text (`<0.0001`, `1.2 to
3.4`, `NaN`, `007`, an excluded value `12.5*`), blank is empty. Title
rows and the row-title column stay text. Data tables keep every stored
digit (the number is written as the shortest text that reads back as the
same double); results are the digits shown, as their CSV is. Values Excel
cannot hold (beyond 1.8e308, or nonzero below 2.2e-308) stay text, so no
value changes on the way in. Sheet names are cut to 31 characters, `[ ]
: * ? / \` become `_`, repeats get " (2)" and "History" is avoided; each
change is listed on the README sheet with its reason, and the toast says
how many names changed. A table over 1,048,576 rows or 16,384 columns is
refused with the sheet and the limit named. The same workbook is
`workbook.xlsx` in the export bundle, and the results strip's Download
menu (CSV, TSV, Excel workbook) writes one results sheet.

`xlsx.test.ts` pins the typing (1/3 as 0.3333333333333333 from
"0.333333333333333314829616256247", 1e-300, -0, 1e21 written "1e+21",
NaN and blanks), the name rules, the limits and the parts;
`bundle.test.ts` the bundle's workbook. `scripts/xlsx-readback.py` reads a
workbook with three independent readers and compares every cell with the
CSV text: openpyxl 3.1.5, python-calamine 0.9.1 (installed into `.venv`
for these tests) and LibreOffice 26.8 Calc over UNO (its CSV and ODS
writers round to 15 digits, so a conversion cannot show what Calc read;
`getDataArray` returns its doubles). All three read the edge cases above
back exactly. `scripts/e2e-share.mjs` exports the example project, checks
one sheet per table and results sheet and every cell against the
bundle's CSVs (number cells where the CSV holds a number), the bundle's
`workbook.xlsx`, and runs the three readers; `scripts/e2e-check.mjs`
downloads the fit's results as .xlsx and finds LogIC50 a number equal to
the CSV's.

## Source data per figure (P-65, 2026-11-24)

A page layout's "Source data (.xlsx)" (in its export group, next to
Export page) writes one workbook: a README sheet, then one sheet per
panel named by its panel letter in the layout's style ("a", "b"; plain,
whether or not the page shows letters). Each sheet holds what the
panel's graph plots, read from the traces it hands Plotly (`gd.data`):
the legend (n and its unit, the test), the test as the results name it
("Unpaired t test, two-sided") with its results sheet, what the centre and error bars are, then sections for the centre
and error bars of each group with n, box statistics, every plotted value
(data set, row, X or the category under it, Y, error bar lengths), the
drawn curve and band. The X and Y columns carry the axis titles, so an
XY fit says its X is log10 of the dose ("X: log[Conc.], M"), as drawn.
A log2, ln or probability axis moves the drawn values into axis units;
`graph/apply.ts` keeps the values before that in the trace's
`meta.odRaw`, and the sheet writes those (data units). On a category axis the
sheet names the category, not the sideways spread of the points. A panel
drawn with WebGL (over 5,000 points) or a box that draws only its
outliers says so: every value is still in the sheet. An unlinked picture
or a graph that was not drawn is named on the README sheet and in the
toast, never left out silently; traces of a kind the sheet does not list
are named on the panel's sheet. The toast also says when the file is over
Nature's 30 MB limit for source data. The export bundle adds the same
workbook for every layout (`layouts/<name>-source-data.xlsx`).

The eLife checklist item "Source data available" (P-09) is met once a
graph of the table is on a page layout, naming the graphs and the layout,
with "Open the layout"; with graphs on no layout it is not met and offers
"Make a page layout"; with no graph it does not apply.

`sourceData.test.ts` checks a column scatter (Control 1, 2, 3, 4: mean
2.5, SD 1.2909944487358056 as numpy `std(ddof=1)`, n 4; Drug 2, 4, 6:
mean 4, SD 2, n 3), plotting order and a hidden group through
`applyFormat`, a log2 axis (8 and 0.5 written, not 3 and -1, error bars
and curve too), boxes, the notes and the workbook's sheet names;
`report.test.ts` the checklist rule. `scripts/e2e-export.mjs` opens
`e2e-fixtures/stage/source-data.json` (panel a: that column scatter under
an unpaired t test, scipy `ttest_ind` t = 1.2180, P = 0.2776; panel b:
the example dose-response with its 4PL fit), downloads the workbook and
checks sheets "a" and "b": the groups' mean, SD and n above, every point
with its row and equal to the drawn trace, the test and the legend with
