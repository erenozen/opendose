# Feature gaps: statistical analyses (lens: statistics)

Read-only research for `.design/features/BRIEF.md`, 2026-11-23. Ids S-nn.

## How this was checked

- **Engine inventory.** All 102 `_HANDLERS` keys in `engine/opendose/api.py`
  (2428-2492, 2708, 3042, 3285, 3557, 3569, 3681, 3754), plus the module
  docstring and public functions of all 82 modules in `engine/opendose/`.
  Every handler key except the simulate and `effect_size` / `trend_test`
  helpers is referenced from `web/src`, so the engine and the UI mostly
  match. A gap below is a gap in both.
- **Grepping before listing.** Each "absent" claim comes from a
  case-insensitive grep of `engine/opendose/*.py` and
  `web/src/**/*.ts(x)` (tests excluded) for the method's names and
  synonyms. The grep terms are given in the Status column.
- **Statsmodels at runtime: available but not shipped.**
  `web/public/pyodide/v314.0.3/pyodide-lock.json` lists statsmodels
  0.14.6, which depends on pandas 3.0.2 and patsy 1.0.2. The site vendors
  only the numpy, scipy and openpyxl wheels, though, and
  `web/src/lib/engine.ts:48` loads only `["numpy", "scipy"]` from
  `packageBaseUrl` (no CDN fallback). Using statsmodels would add
  pandas, patsy and statsmodels on top of the 30 MB first visit that
  `docs/design/DECISIONS.md` §0.3 calls the product's biggest risk. Every
  row below is therefore planned on numpy and scipy (1.18), with
  statsmodels, pingouin, lifelines and R as **native test oracles** in
  `engine/tests/`, as 17 test files already use statsmodels. The ROADMAP
  ("Engine (all waves)") notes that no R was available. Rows whose only
  good oracle is R say so.
- **Already shipped despite ROADMAP / needs.json saying open.** I
  verified these and they are not findings:
  - one-tailed t, Mann-Whitney and Wilcoxon: `ttests.py:82` `one_sided_t`,
    `p_greater` / `p_less`
  - exact Kruskal-Wallis: `anova.py:562`, `exactdist.kruskal_wallis_exact_p`
  - Kenward-Roger and Satterthwaite df: `ddfm.py`
  - lag-1 autocorrelation: `columnstats.lag1_autocorrelation`
  - Kb next to pA2: `schild.py:134`
  - delta-method ED50 CIs and a parallel-line relative potency for quantal
    data: `quantal.py:512`
  - Dunn's test against a control and for planned pairs:
    `repeated.dunn_scope`, `anova.planned_pairs`
  - RM post hoc: `rm_posthoc.py`
  - EC50 ratio between two curves: `compare_params.py:115/255`
  - Cox regression: `cox.py:501`
  - Hosmer-Lemeshow: `multivar.py:561`
  - MuSyC and synergy for three or more drugs: `musyc.py`,
    `synergy_multi.py`
  - Fligner-Killeen; weighted kappa: `trend.py:377`
  - generalized CMH: `trend.cmh_general`

## 2. Not feasible / out of scope

- **Loading statsmodels (or pandas or patsy) in the browser.** It is in
  the Pyodide lock, but it is not vendored and it would add to the 30 MB
  first visit (DECISIONS.md §0.3). Every row above is planned on
  numpy/scipy. statsmodels stays the native test oracle.
- **MCMC-based Bayesian models** (BEST, hierarchical brms-style models).
  Thousands of likelihood evaluations in WASM, plus convergence
  diagnostics a bench user cannot judge, break the "caveats stated
  plainly" promise. Only closed-form or 1-D-integral Bayes factors (S-03)
  fit.
- **Fine-Gray subdistribution-hazards regression.** It is feasible, but
  L effort for a rare preclinical need. Cumulative incidence plus Gray's
  test (S-34) covers the descriptive and comparative question.
- **Nonlinear mixed-effects dose-response** (NLME across experiments).
  It is L effort and numerically fragile in the browser. S-36 (summary
  across experiments) and S-40 (meta-analysis) answer the same question
  honestly.
- **Exact (conditional) logistic regression** (LogXact). It is
  combinatorial. Firth (S-19) covers small-sample separation.
- **Group-sequential and adaptive designs, interim analyses, MANOVA,
  discriminant analysis, structural equation models, multiple
  imputation, ARIMA / spectral time series, machine-learning
  classifiers.** These are outside the bench-experiment promise, and no
  existing surface (data grid, Analyze menu, results pane) presents them
  without a new product area.
- **Williams' test from published tables only.** The tables cover a
  limited range of k and df. S-11 is listed "with care" because it needs
  a Monte Carlo critical value with a fixed seed. If that cannot match
  PMCMRplus to the reported precision, drop it in favour of S-10 plus
  Dunnett.

## 3. Top 10 by value ÷ effort

1. **S-36 Potency across experiments.** This is the number almost every
   pharmacology paper reports ("IC50, 95% CI, n = 3 experiments"). It is
   pure arithmetic on fits that already exist, and it fixes the "curve
   fits use every value" pseudoreplication gap on XY.
2. **S-01 Equivalence / TOST.** It turns the most common misreading
   ("ns = no effect") into a test with a verdict. It is built from
   `one_sided_t`, which already exists. S effort.
3. **S-29 Compare slopes and intercepts.** A long-standing partial need
   (#139) and part of the comparable regression result elsewhere.
   Closed-form OLS, S effort.
4. **S-15 Pairwise proportions after r × c.** It answers the question
   every chi-square raises. It reuses `fisher_exact` and `fdr.adjust`,
   and the contingency graphs already exist for the brackets.
5. **S-02 Ratio / % of control with a Fieller CI.** This is the bench's
   favourite summary, currently printed without uncertainty
   (`meaning.ts:221`). `fieller_ratio` already exists.
6. **S-22 Repeated-measures correlation.** It closes the
   pseudoreplication hole in correlation, which is as common as in t
   tests. Closed form, S effort, with a Python oracle (pingouin).
7. **S-06 ANCOVA for baseline-adjusted comparisons.** A partial need
   (#149). It is more powerful and more honest than % of baseline, and
   the OLS engine is already in `multivar.py`.
8. **S-16 Overdispersed counts (quasi-Poisson first, then NB).** The
   dispersion is already computed and warned about. Quasi-Poisson is one
   multiplication, and it stops t tests on counts.
9. **S-27 Passing-Bablok.** The one gap named inside an otherwise "done"
   need (#106). It is S effort with the existing order-statistics
   selection, and it has an R oracle with example data.
10. **S-30 General LMM with covariates and two nested levels.** It
    addresses the highest-volume partial need (#3, 75 observations:
    animal / slice / cell). REML and the KR/Satterthwaite df already
    support several variance components, so this is mostly
    design-matrix and UI work.
